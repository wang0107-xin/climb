# 阶段 2 落地说明（2.1 静态分析 + 2.2 安全扫描 + 2.3 并行）

> 阶段 0 / 阶段 1 的手工步骤在 `stage0-runbook.md`。这份只讲阶段 2 第一个模块。
> 阶段 2 一共有两个模块：**这个（2.1+2.2+2.3）**和 **2.4 可观测性校验**。为什么 2.4 不一起做，见文末。

---

## 一句话

把 ruff 和 bandit 装进**已有的** `python` 容器，放**同一个并行块**里跑，
各出一份报告，交给质量门禁汇总。没有新增容器、没有新增镜像、没有新增常驻服务。

| 文件 | 作用 |
|---|---|
| `ci/static_analysis.py` | 驱动器：跑工具 → 归一化报告 → 打摘要。本地也能直接跑 |
| `ruff.toml` | 规则集（**显式写死**，不跟 ruff 默认值走） |
| `requirements-dev.txt` | 多了 `ruff==0.16.9`、`bandit==1.8.6` |
| `Jenkinsfile` | 新 stage「静态分析与安全扫描（并行）」，位置在**构建镜像之前** |
| `ci/quality_gate.py` | 多两行检查：`静态分析(ruff)`、`安全扫描(bandit)` |
| `reports/ruff.json`、`reports/bandit.json` | 两份报告（已被 `archiveArtifacts` 归档） |

**这次实测的基线**：ruff 20 条、bandit 0 条。见下面「基线」一节。

---

## 本地怎么跑（不用起 Jenkins）

```bash
cd demo-project
python ci/static_analysis.py ruff      # -> reports/ruff.json
python ci/static_analysis.py bandit    # -> reports/bandit.json
python ci/quality_gate.py              # 观察期：只汇总，rc 恒为 0
python ci/quality_gate.py --enforce    # 门禁期：有失败项 rc=1
```

前提是本地装了这两个包：`pip install -r requirements-dev.txt`。

> 本地跑不需要 `reports/` 里其它文件。缺 `junit.xml` / `deploy.env` / `smoke.json` 时，
> 门禁会把对应那几行标成 `—`（未产出），不当失败 —— 这是刻意的，
> 免得"分支只构建不部署"或者单独跑一个环节时门禁凭空报红。

## 报告怎么看

三个地方，看的东西不一样：

1. **构建日志**里那一段 `[static_analysis] ruff：20 条（I001 11、BLE001 2、…）`，
   后面跟每条明细的 `文件:行:列 规则码 说明`（默认最多列 50 条）。日常看这个就够。
2. **构建页面左侧「构建产物」**里的 `reports/ruff.json` / `reports/bandit.json` —— 全量明细，
   每条都有 `file` / `line` / `col`。
3. **`gate-summary.md`** 里的汇总表，把前 3 条的 `文件:行` 直接写在表格里 ——
   这是为了满足阶段 2 的验收标准「每类问题都能在报告里定位到具体文件行号」：
   在门禁表上就能看见行号，不用再去翻 json。

## 基线（首次跑出来的）

**ruff 20 条**，按规则码分：

| 规则码 | 条数 | 是什么 | 好修吗 |
|---|---|---|---|
| `I001` | 11 | 导入块没排序 | 好修，`ruff check --fix` 自动改（16 条可自动修） |
| `BLE001` | 2 | 盲吞 `except Exception` | 要人判断：`app/routes.py:17` 那条是**故意的**（错误响应里要返回原因） |
| `F401` | 1 | `flask.request` 导入没用 | 删掉即可 |
| `F841` | 1 | 局部变量 `e` 赋了没用 | 删掉即可 |
| `G201` | 1 | 该用 `logger.exception` 却用了 `.error(exc_info=True)` | 一行的事 |
| `DTZ005` | 1 | `datetime.now()` 不带时区 | 要判断：这个项目只记"什么时候抓的"，加不加时区是产品决定 |
| `RUF012` | 1 | 类属性用了可变默认值 | 改 `ClassVar` 或挪进 `__init__` |
| `TRY201` | 1 | `raise e` 写成 `raise` 更好 | 一行的事 |
| `TRY300` | 1 | `return` 放在 `try` 里、建议挪到 `else` | 要人看，可能只是风格 |

**bandit 0 条**：跳过 `B104`（绑 `0.0.0.0`）之后，`app` + `wsgi.py` 里没有安全类问题。
跳过 B104 的理由写在 `ci/static_analysis.py` 里：容器里绑 `127.0.0.1` 等于自绝于 Pod 之外，
访问控制由 K8s 的 Service / NetworkPolicy 承担。**留着它只会得到一条永远消不掉的告警，
而一条永远不消的告警会教会所有人忽略整个报告。**

## 规则集怎么调（`ruff.toml`）

`select` 是**一条条写出来的**，不是按族写的，也不靠 ruff 的默认值。原因有两个，都是实测出来的：

1. **默认值会跟着版本变。** 实测 ruff 0.16.9 的默认集里已经带了 `I001` / `BLE001` / `RUF012`
   这些以前要显式开的规则 —— 升个版本，"基线有多少条"就自己变了，而条数正是观察期要盯的东西。
2. **按族选会淹掉有用的。** `"RUF"` 整族选进来，`RUF001/002/003` 会把**所有全角标点**
   报成"歧义字符"。这个仓库的注释和字符串全是中文，实测一次冒出 288 条，
   而真正有用的 `RUF012` / `RUF100` 会被埋在里头看不见。所以写的是 `"RUF012", "RUF100"`。

**加规则的正确顺序**（不然会被一次涌入的告警淹没）：

```bash
# 1. 先在本地试，看会多出多少条、都是什么
python -m ruff check . --select 想加的族 --statistics
# 2. 觉得能治，再写进 ruff.toml 的 select
# 3. 本地跑一遍 python ci/static_analysis.py ruff 对比条数，差异看清楚了再提交
```

**明确不开的族**（理由都写在 `ruff.toml` 里）：`S`（和 bandit 重复，分工是 ruff 管规范、bandit 管安全）、
`E501`（行长）、`ANN`/`D`/`N`/`COM`（类型注解/文档字符串/命名/尾逗号这类团队约定，不是"代码有问题"）。

## 什么时候从"观察期"升级成"卡点"

阶段 2 现在**不阻断**：`ci/static_analysis.py` 发现问题也返回 0，条数只是被门禁记下来。
这是规划「原则 3」的要求 —— 先出报告，看几轮失败率，再决定卡不卡。

升级顺序（**先让 ruff 归零，再开门禁**，否则第一次开 `ENFORCE_QUALITY_GATE` 就会红）：

1. 把 20 条清掉。先跑 `python -m ruff check . --fix`（能自动改 16 条），剩下的按上表逐条判断。
   **判断结果有三种，不是只有"改代码"一种**：
   - 真问题 → 改代码
   - 有意的写法（比如 `app/routes.py:17` 那条盲吞）→ 加 `# noqa: BLE001` 并写一句为什么
   - 规则本身不适合（比如 `DTZ005` 对这个项目）→ 写进 `ruff.toml` 的 `ignore`
2. 确认 `python ci/static_analysis.py ruff` 报 0 条、`bandit` 报 0 条。
3. 把 `Jenkinsfile` 里的 `ENFORCE_QUALITY_GATE` 改成 `true`。
   注意它是**整个门禁的开关**，不只是这两项 —— 打开之后，单元测试失败、副本没就绪、
   Pod 重启过这些会一起开始阻断（它们本来就该阻断，之前只是观察期）。

## 阶段 2 的验收怎么跑

| 验收标准 | 怎么验 |
|---|---|
| 每类问题都能在报告里定位到具体文件行号 | `reports/ruff.json` 每条都有 `file`/`line`/`col`；`gate-summary.md` 的表格里也直接写了前 3 条的 `文件:行` |
| 并行后总构建时长没有明显增加 | 构建页面左侧「流水线步骤耗时」里看那两个并行分支的耗时（应该是秒级）。**真正的开销不在扫描，在 `pip install` 多装两个包那一步** —— 十几秒，一次性的 |

想确认这两步**真的在扫描**（而不是"每次都 0 条"），故意改坏一次最快：

| 把什么改坏 | 应该红在哪 | 报什么 |
|---|---|---|
| 在 `app/routes.py` 顶部加一行 `import os`（不加使用） | 静态分析（并行块里） | ruff 多一条 `F401`；**观察期不会让构建变红**，只在门禁汇总表里变成 ❌、条数 20→21 |
| 在 `app/` 的任意文件里写一句 `subprocess.run(cmd, shell=True)` | 安全扫描（并行块里） | bandit 报告里出现 `B602 HIGH`（外加一条 `B404 LOW`，提到 subprocess 就有一条）；同上，观察期只记录 |
| 把 `ci/static_analysis.py` 里 `TOOLS['ruff']['ok_codes']` 改成 `{0}`（谎称"有告警=出错"） | 静态分析（并行块里） | `[static_analysis] ruff 没跑起来：ruff 退出码 1（工具出错，不是发现问题）`，**这次真的红** |

最后一行是关键的一条：**"工具出错"和"发现问题"必须是两种结果**。
一旦它们混在一起，报告消失 + 门禁判成"未产出" = 一路绿着过去，那才是最坏的情况。

## 踩过的坑

### 1. `"RUF"` 整族开会冒出 288 条中文标点

见上面「规则集怎么调」。要点：**ruff 的族（family）选法很危险**，`E4`/`F` 这种族内部一致性高，
但 `RUF` 是个大杂烩（`RUF001` 查全角标点、`RUF012` 查可变默认值、`RUF100` 查无用 noqa）。
中文项目里整族开 RUF，等于给自己造 288 条噪音。

### 2. bandit 的 `.bandit` 配置文件放仓库根**不生效**

第一版想按惯例在仓库根放个 `.bandit` 写 `skips = B104`，实测没生效。翻 bandit 源码
（`bandit/cli/main.py` 的 `_get_options_from_ini`）才看清规则：

> 它是在**你指定的扫描目标目录里逐个 walk 找 `.bandit`**，不是"在当前目录找"。

所以 `bandit -r app wsgi.py` 永远看不到仓库根那个文件（除非目标里包含 `.`）。
三条路：放进 `app/`（丑）、每次加 `--ini .bandit`（要记着）、或者干脆写在命令行参数里。
**选的是第三条** —— 一条 `-s B104` 而已，写在 `ci/static_analysis.py` 的 `TOOLS` 里，
就在它的说明旁边，比藏在一个配置文件里更好找。

### 3. 为什么不用 shell 写 `ruff ... || true`

`|| true` 会把"发现了 20 条问题"和"ruff 根本没跑起来"变成同一件事。
后者更危险：报告没产出 → 门禁看到 `reports/ruff.json` 不存在 → 判成"这一环没启用" → **一路绿着过去**。

所以 `ci/static_analysis.py` 干了三件 shell 里不好干的事：
分辨退出码（ruff 的 0/1/2 含义不同，bandit 得靠 `--exit-zero` 才分得开）、
工具出错时**写一份带 `error` 的报告**（让门禁判失败，而不是当没启用）、
归一化两份格式不同的 JSON。

**一句话**：门禁读不到报告和门禁读到"跑挂了"，必须是两种结果。

## 下一步：2.4 可观测性校验（不在这一个模块里）

规划里的「加入节奏」写着：**一次只加一个模块，连续绿 3 次再进下一个。**
这个模块（2.1+2.2+2.3）是第一个，它在 `Jenkinsfile` 里是一个独立的 stage、
有 `RUN_RUFF` / `RUN_BANDIT` 两个开关、改动只落在自己的文件上 —— 先让它跑绿 3 次。

2.4 要做的是（规划里说的 L1+L2，只做这两层）：

- **L1 部署后断言**：探针通过、Pod 无重启、日志里没有 ERROR、结构化日志字段完整。
  代价≈0，复用现有的 `kubectl` 容器，把 `reports/deploy.env` 那个套路扩一扩。
  这个项目的日志已经是 JSON（`endpoint`/`method`/`path`/`duration_ms`），所以 L1 几乎是白送的。
- **L2 指标端点**：应用暴露一个指标端点，流水线只断言"端点可达且含关键指标名"。
  要动应用代码（pip 一个包 + 改几行）+ 改两份清单。

L3（真部署 Prometheus + Grafana）和 L4（Jaeger）是 GB 级常驻内存，规划里明确暂缓。
